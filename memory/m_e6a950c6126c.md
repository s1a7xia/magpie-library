开发项目时优先完成可运行的功能闭环，再根据实际效果迭代。对尚未确认但低风险、可逆且不阻塞闭环的细节，先按合理默认方案完整实现，不因等待确认留下空壳；需要后续确认时用 TODO 写明当前方案、待确认点和调整条件。涉及资金、权限、不可逆数据变更或实质影响业务正确性的关键规则，不擅自默认决定，应先取得必要确认或授权。开发大型、跨会话或多阶段项目时，以项目内状态文档作为任务事实源，以 Git 作为代码事实源；状态文档持续记录当前阶段、已完成、进行中、下一步、剩余任务、风险、阻塞和验收状态，开始工作前核对文档与 Git 的实际状态，任务结束后及时更新。文档不得长期滞后于代码；小改动只更新相关状态，不额外制造文档。“先跑起来”是交付优先级，不自动授权启动、测试或部署，仍遵循当前任务的执行范围。
