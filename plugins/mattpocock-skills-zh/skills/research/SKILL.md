# Research

启动一个后台子代理执行调研，主会话继续推进其他工作。子代理使用全新 context window，只负责只读查证和在当前任务授权的 notes 位置写入调研结果；不得修改产品代码、测试、提交、推送、部署或写外部系统。如果后台子代理不可用，就在当前会话完成调研并明确说明这一执行方式。

## 调研

1. 对照 **primary sources** 调研：official docs、source code、specs、first-party APIs，而不是二手解读。每个 claim 都要能追溯到拥有该事实的 source。
2. 把 findings 写入一个 Markdown 文件，并为每个 claim 标注 source（URL、版本、commit 或文件路径）。
3. 保存到项目既有 notes 位置并匹配现有 convention；没有 convention 时放在合理位置并明确路径。只写当前任务授权范围内可修改的文档。
4. 区分 **已核实事实**、**合理推断** 和 **未知**；版本、价格、API 行为等易变事实要核对当前一手来源。无法访问时明确报告限制，不用记忆冒充验证。
5. 把结果带回当前决策，不只丢一份链接清单。说明哪些事实会改变方案、哪些仍待用户决定。

## 边界

- 不在未授权时创建 Issue、PR、提交或 push。
- 数据不足时说明缺什么、建议如何获取，不猜测或编造引用。
