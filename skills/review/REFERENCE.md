# Review: Detailed Reference

## Chapter 1: Context Collection

先确定本次要审的切片与提交，不以工作区是否干净决定是否有可审代码。

- 从 PRD、批次交付记录或 `docs/agents/verification.md` 取批次开始前的 base、批次 head 和切片提交清单。连续且只含本批改动时，用 `git diff <base> <head>`；同时查看提交清单，确认范围。
- 同一分支夹有其他任务提交时，按已确认清单用 `git show <commit>` 检查各片，再结合当前文件和调用方核对最终行为，不把其他任务全部扫入。
- 用 `git diff`、`git diff --cached` 和相关未跟踪文件检查本任务未提交改动。工作区有变化也不能因此漏掉已提交切片。
- 只有明确是分支/PR 审查时才用已验证的 merge-base 或 PR diff。默认分支上的 `main..HEAD` 为空不能证明没有改动。
- 缺记录先查 `git log` 的切片标识；无法可靠划定范围才问用户。报告实际 base/head、提交清单及未提交范围。

读取当前需求、相关代码、调用方和适用规范一次，三个视角复用事实，各自核实结论（[共享规则 #35](../rules/anti-patterns.md)）。大差异按模块分组，风险高的实现读必要上下文，不能只凭搜索片段下结论。只读当前范围需要的配置和 ADR。

## Chapter 2: Verification Evidence

- 验收标准是否有对应实现与实际证据；页面、角色和边界是否在声明范围内。
- 阶段顺序与证据回流见 [共享契约](../rules/workflow-contract.md#4-验收门槛与回流)：默认先手动 review，再手动页面验收；首次覆盖完整声明范围，不自动启动下一阶段。
- 编译、页面验收的代码版本是否仍适用。检查后相关源码、依赖、构建配置或运行环境发生变化时，定位受影响证据；文档提交不自动作废代码验证。
- UI 视觉结论有渲染截图；编译或源代码检查不能证明页面可用。
- 现有或用户要求的测试是否验证行为、覆盖相关边界、避免错误 mock；测试检查只在当前请求授权或更高优先级指令明确要求时执行；项目命令列表不授权。默认无测试时记录 `Tests: not run — outside current request`，不新增、不运行测试，也不把缺少测试本身列为缺陷；授权测试缺失关键验收覆盖或掩盖真实缺陷时才是 blocker。
- 检查失败、未执行、用户确认与代理实测分开记录。

## Chapter 3: Code Review

按当前 profile 和相关调用链检查：需求/字段契约、参数校验、权限与数据边界、事务/并发/幂等、错误处理、框架能力复用以及本次涉及的性能问题。只加载任务相关规范，不扫全库做泛化加固。

具体缺陷必须说明可发生的后果。凭据泄露、越权、数据丢失或阻断主功能等按实际风险列为阻塞；缺少某种设计模式不构成缺陷。[工程原则](../rules/engineering-principles.md)只用于解释具体影响，不按清单强行重构。

## Chapter 4: Impact Review

检查受影响调用方、数据兼容性、共享组件、跨切片流程和权限传播。数据库变更涉及已有数据时核对迁移与必要回退安排；涉及新表、表关系、唯一性、删除语义或索引时，按项目数据库设计入口（未配置时为 `database-design`）核对业务不变量、约束、引用、查询路径和迁移安全。整批审查需串起切片间数据流和验收标准覆盖，不能只逐文件看正确性。

有明确推荐实现且记录待业务确认的 TODO，不因关键词就认定功能未实现；核对其默认行为、影响及确认事项。会改变验收结果的未决规则不能伪装成已完成。

## Chapter 5: Report

一份报告即可：

- 审查范围：base/head 或提交清单，相关未提交变更。
- 发现：严重程度、文件位置、触发条件、后果、建议；合并重复问题。
- 验证：实际有效的编译/页面/其他检查，未验证项。
- 结论：通过 / 需修复 / 证据不足；实际状态与下一步。

不要为了填模板制造正面评价、三个独立长报告或要求用户批准已有授权动作。

## Chapter 6: Follow-through

生命周期以 [PRD 格式](../think/PRD-FORMAT.md#prd-生命周期状态) 为准。确认缺陷在已授权范围内登记并进入 debug；仅建议不自动实施。修复改变已验收行为时记录受影响切片和证据失效原因，但继续完成本轮剩余审查，不因单个修复中断。

详见 [共享阶段契约](../rules/workflow-contract.md)：默认先手动 review，再手动页面验收；不自动启动任一阶段。

收尾更新 Review、Page acceptance、Close-out 和最终代码范围；只读请求不写回。普通提交推送遵循项目授权。

## Chapter 7: Session Recovery

恢复时核对审查范围、当前差异和已有发现；有变化的部分重新检查，其余沿用仍有效的证据。

## Chapter 8: Integration Review

整批收口额外检查切片间契约、共享状态、依赖顺序和 PRD 验收标准覆盖。验证仍只在授权范围执行，不自动扩大为全库回归。
