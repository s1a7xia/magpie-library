# Review Reference

## 范围与证据
审查未提交改动时区分暂存、未暂存和用户已有修改；审查分支时使用实际基线，不猜默认分支。读取变更处的实现及必要调用方，不默认扫描整个仓库。

## 检查视角
- 实现：真实输入、边界、状态转换、错误处理、权限、项目规范及具体安全风险。
- 测试：相关已有用例验证了什么，是否隔离正确，是否遮蔽真实行为；不因新代码缺少新测试一律拒绝。
- 影响：接口、旧数据兼容、生命周期和跨模块调用；多个切片交付时核对它们之间的数据流与共享状态。
- 持久化模型变化加载 database-design；实际 RuoYi 项目改动叠加 ruoyi6。

## 独立审查
仅明确授权才委派；提供目标、差异基线、相关路径和只读边界。独立审查者自行读取相关证据，不要求全量重读或固定人数。无工具时如实说明，不把主代理复看称为独立审查。
主代理核实结论并去重；分歧先对照代码与证据，未解决时标明未知，业务取舍才询问用户。

## 输出格式
按严重程度列出可行动问题，每项含文件位置、触发条件、具体影响和建议。没有发现就说明没有发现，不制造问题；列明审查范围和未执行的检查。

## 修复、验证与收尾
只读审查不写产品文件或文档。授权审查中修复时仅修有效缺陷并复核，不顺带重构。运行检查与新增测试分别判断授权；实际失败不能隐藏。只同步实际受影响且获授权的文档，远程 Issue、提交、推送和发布不随审查通过自动执行。
