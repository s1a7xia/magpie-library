# 三方协作

Magpie 管共享指令、技能与工具配置；Codex 负责用户交给它的开发与交付任务；普通 dsh 项目遵循用户当前需求和项目规则，可正常开发、测试和执行已授权 Git 操作。

## 微信入口

微信只适用于 `~/.dsh/im`，默认日常聊天、按条消息分流。进入项目动作、普通聊天输出、进度/总结、需求入仓、联网调研及明确归档的完整规则，只以该目录 `AGENTS.md` 和 `REPORTER.md` 为单一事实源；本技能不复制触发词或报告模板。

微信不开发、不测试、不改项目最终状态。受控脚本只能写已登记项目的 `docs/inbox/<需求ID>/` 或明确要求归档时的 `docs/research/inbox/<RES-ID>/`；业务 Git 由 Codex 收尾。调研简报是待核验材料，不是正式 `docs/research/` 记录，也不更新 INDEX。Codex 续接时复核原始来源后再决定采纳、补证或晋升。

## 需求与交接

需求默认使用独立目录，不默认进入 Issue。微信助手不能修改业务代码、最终状态和验证记录，不运行测试；仅可通过受控脚本把本条文字需求和文件附件写入已登记项目的 `docs/inbox/<需求ID>/`，精确提交并推送该需求目录，不得直接操作任意业务路径或把其他暂存改动裹入提交。辅助项目的需求附件只按文字或文件处理；无前缀的纯图片/截图属于日常聊天，不因收到图片自动触发归档。Codex 接收需求后负责方案、实现、受影响前后端的编译检查、文档及业务 Git 收尾。

本机目录不等于共享 Git。已登记项目可由微信通过受控入仓脚本直接发布本条需求与附件；项目未登记、分支或上游不满足保护条件、附件不可读或脚本未提供时，不得伪称已入 Git。记录实际路径、提交和远端；不把本地路径当远程链接，不声称 Codex 自动接单。

已有 Issue/PR 仅在用户明确选择使用时作为任务关联，不自动创建。不假定共享文件系统、未提交修改或会话历史。并发编辑同文件前先划分归属。

状态回答依据项目状态文件和可核对的 Git/验证证据；无证据写待确认，区分实施、验证和交付。
