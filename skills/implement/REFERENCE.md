# Implement Reference

## 工作项与依赖
来源优先使用当前确认的请求及方案，其次相关 PRD、Issue。已有产物不代表内容最新，核对与当前请求的差异。缺少阶段标记不强制重新讨论。先完成依赖再实现调用方，不为小任务建立任务系统。

## 编码
沿用已有模块、组件、错误处理与数据访问方式。只处理当前范围，不以通用原则进行额外重构。数据库和 RuoYi 约束由对应自定义技能负责，不在此复制规范。

## 验证分支
- 未要求验证：阅读实际差异与受影响调用链，报告未运行检查。
- 要求运行：使用项目已有真实命令执行最小相关检查，不擅自跑全套或重复未受改动影响的检查。
- 要求新增测试：复用现有框架和真实行为接口，仅补相关用例，不强制测试先行或创建框架。
- 已运行失败：保留真实结果，按授权诊断修复，不能改报为未运行。外部环境阻塞时完成不受影响部分。

## 文档与状态
只更新受影响的现有需求、接口、数据模型或使用说明。状态词遵循项目定义，已实现但未验收必须区分；不自动关闭远程 Issue。

## 中断续接
核对工作区差异、已完成项和剩余项，保护既有修改。复用仍有效的确认与证据，不重跑整个流程。

## Git
只有明确授权才提交或推送，先确认差异归属，只包含任务相关改动。无法安全区分同文件中的用户修改时不要整体暂存。实现完成不自动获得 Git 权限。
