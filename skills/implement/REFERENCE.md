# Implement — 批次、记账与恢复

## 切片与覆盖

读取 PRD `Traceability → Sliced into` 中的稳定本地 ID 或远端 Issue，验收标准与依赖必须可定位。远端未发布不等于无切片；无权限不切换 tracker 或自动发布。按 `blocked-by` 排序，阻塞片保留 In Progress，其余可继续。

开工前检查每条 R#/AC# 的 Covers；未分配的标准报告给用户处理，不在 implement 发明切片。收尾时除了检查映射存在，还要核对标准对应代码确实完整；一片完成不能替整批写完成。

## 证据和状态

按 [共享状态契约](../think/PRD-FORMAT.md#prd-生命周期状态) 记实现状态；检查和 Git 不混进 Dev Complete 的定义。建议使用已有记录的以下字段，不强制建新表或文件：

| 项 | 内容 |
|---|---|
| Scope | PRD、切片 ID、R#/AC#、相关模块 |
| Version | 批次 base、最终实现 head、逐片提交；未提交改动也需声明 |
| Implementation | 完整 / 缺行为 / 已知代码缺陷 |
| Verification | 命令、目录、退出状态、结果与覆盖版本；未运行写原因 |
| Git | 未授权 / 未提交 / 已提交 hash / 已推送上游 / 阻塞 |
| Follow-up | TODO 当前默认、待确认、调整点、确认人，手动下一步 |

当前请求要求构建/测试时，从实际构建配置选最小目标。只要求运行已有测试不新增测试；无授权不运行检查。复用仍覆盖最终代码的成功证据，代码/依赖/构建配置相关输入变了才重验。页面验收始终另由用户发起。

## 文档与 Git

每片更新自身状态，批次收尾集中更新项目状态和验证证据。只更新已有且适用的文档，不为了固定仪式触碰全部文件。按 [自动收尾契约](../rules/workflow-contract.md#6-工作区自检与自动收尾) 处理已授权 Git：精确暂存、当前分支、保护旧暂存、不 add -A、不自动建 PR/合并/部署。

提交信息示例：`[PRD-NNNN] <slice ID/title> — <actual change>`。不要用 `Closes #...` 自动关闭尚未审查/验收的 Issue。Git 无授权或推送失败只记录对应缺口，不回滚实现或伪造推送成功。

## 恢复

- **检查失败**：读错误，区分代码、依赖、环境与命令问题，不武断归因于切片依赖顺序。已知代码错误保持 In Progress；环境阻塞可与代码完整并存，但验证不能写 pass。
- **命令不明**：读构建文件/已验证运行说明；缺失则报告未验证，不发明命令。
- **混杂改动**：停止无法安全分离的写入或 Git 动作；保留原状，不 stash/reset/clean。
- **基线被事实推翻**：停受影响片并给证据与用户所需决定；不自动联网调研或改需求。
- **首次页面验收缺失**：review 修复点不能替代完整声明范围；只在已有其他范围有效证据时局部复验。
