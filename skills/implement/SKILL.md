# Implement

## 完成契约
完成当前授权范围内的工作项并核对实际差异，区分实现完成和运行验收。未授权测试不阻塞实现交付；若用户要求验收，不能用代码检查代替验收结果。

## 流程
1. 读取请求、项目约定、相关实现和已确认方案。沿用现有文档；不要求先有 PRD、Issue 或 docs/agents。
2. 按依赖顺序提取工作项，简单改动直接完成，不机械拆分。只询问影响正确性或范围的关键歧义。
3. 主代理直接实现，复用项目能力，保护用户改动。适用 RuoYi 项目加载 ruoyi6；持久化模型变化加载 database-design。不依赖未安装的测试流程。
4. 每个相关改动核对差异、调用关系及契约。默认不写、不改、不运行测试，不运行 lint、类型检查、构建或浏览器；明确要求运行验证时执行对应最小范围。运行测试不自动授权新增测试。
5. 同步实际受影响的既有文档。实现状态与验收状态分开，不把“代码写完”直接标成“验收通过”。
6. 普通改动聚焦核对即可；明确要求审查时使用 review。独立审查或委派需明确授权，提交、推送、合并与发布分别按授权执行。

复杂切片、失败恢复或文档状态同步时按需读取 [REFERENCE.md](REFERENCE.md)，不要默认加载全部阶段。

## 输出
报告完成项、关键变化、实际检查与未验证边界。有阻塞说明原因；无须固定下一步命令、额外审批或报告文件。
