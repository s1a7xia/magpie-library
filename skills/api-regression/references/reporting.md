# 结果与清理

复用项目已有验收清单，报告：

| 场景 | 版本/角色 | 断言与证据 | 结论 | 未验证边界 |
|---|---|---|---|---|

`断言与证据` 写清 API 观察值和数据库 MCP 的关键 ID/终态；只写查询目的和关键字段，不粘贴完整结果集或凭据。

结论只使用：

- `PASS`：约定主路径和关键拒绝分支都在当前版本实际通过；
- `FAIL`：当前版本违反预期，附业务码、关键响应和终态；
- `PARTIAL`：关键环节通过，但场景要求的环节仍缺；
- `BLOCKED`：缺环境、设备、凭据、外部系统或授权，明确缺失项。

保留运行命令、用例数量、失败原因、耗时、数据清理状态和受影响缺陷，不堆完整请求日志。零用例、全部跳过或运行器自身失败不能记为通过。

## 缺陷与复测

已有修复授权时，只修确认的范围内缺陷并复测受影响路径；仅测试请求则报告。修复后的用例要能识别原错误行为，不削弱断言迁就现状。

## 清理

只删除本轮有归属证明且获准删除的测试数据。共享库不做无范围清空。被客户演示引用或归属不明的数据保留并说明。清理失败时保留脱敏证据，报告剩余对象。

## 停止

覆盖约定范围后停止，不自动扩大到全量 CRUD、性能、安全渗透、部署或页面检查。编译、接口连通和 Skill 校验通过都不等于业务验收通过。
