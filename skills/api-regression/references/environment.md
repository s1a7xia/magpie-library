# 环境与执行

## 最小确认

在发写请求前确认：

- 目标代码版本、运行实例和端口；
- 前端/API 地址与目标数据库、缓存、队列、调度器；
- 环境是否允许写业务数据，以及允许的范围；
- 外部依赖会访问哪里，是否可能产生真实通知、扫描、支付或客户数据；
- 本轮唯一 run ID 和数据清理责任。

不能确认目标是获准测试环境时，只做只读检查。启动隔离实例、克隆数据库、重置账号、扩大权限、执行 SQL 和清理共享数据分别按实际授权执行。

## 运行器

优先复用项目已有的测试生态和 HTTP/RPC 客户端。没有现成框架时，可用语言标准库或项目依赖写一个最小运行器，避免为 API 回归引入完整框架。

运行器至少应支持：

- 从受保护输入加载认证信息，不打印敏感值；
- 为每个角色保存独立会话；
- 记录请求方法、路径、业务码、耗时和失败摘要；
- 为一次运行生成唯一 ID；
- 明确退出码；零用例、跳过或失败不能返回成功。

## 依赖隔离

随机 HTTP 端口不能隔离数据库、Redis、消息队列、对象存储和调度器。克隆数据中的真实外部地址和令牌不得在测试中直接使用。外部集成应禁用、指向本地替身，或把真实集成单列为未验证。

## 数据库 MCP

已连接 dbhub 等数据库 MCP 时，先在只读环境确认 schema 和表，再用精确 ID 做有界查询。数据库 MCP 不替代 API 主路径，也不能用于直接改状态、制造账号或修复测试数据；只读核对规则见 [数据库只读核对](database-verification.md)。

## 无 MCP 时

- HTTP/RPC：使用项目客户端、`curl`、PowerShell `Invoke-RestMethod`、Node/Python 等标准能力。
- 数据库：优先用业务查询接口；获准时可使用项目已有数据库客户端或标准 CLI。
- 任务日志：读取应用日志、任务历史接口或项目已有查询页面。
- 登录态：使用用户导出的 storage state、受保护的 Token/Cookie 文件或本地测试账号文件。
- UI：仅在用户明确要求页面运行检查且确有需要时使用现有浏览器能力；否则单列 UI 未验证。

MCP 是便利层，不是测试前提。数据库 MCP 已连接时优先用于关键持久化断言；未连接时，API 主路径仍可执行，但事务、跨表一致性等数据库专属证据必须标为未取得。
