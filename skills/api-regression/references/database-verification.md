# 数据库只读核对

数据库 MCP（如 dbhub 的 `search_objects`、`execute_sql`）用于证明 API 之外的持久化事实：事务是否提交、状态是否一致、历史快照是否保留、权限过滤是否真的落到 SQL 范围。它是业务 API 的补充证据，不是绕过 API 的测试入口。

## 使用前提

1. 目标必须是获准测试环境；连接信息、库名和 schema 与当前运行版本一致。
2. 只读查询，不执行 `INSERT`、`UPDATE`、`DELETE`、DDL、批量修复或清库。测试数据通过 API 或页面创建。
3. 查询条件使用本轮 API/页面响应中的精确 ID、编号或唯一业务键；不做无界全表扫描，不输出完整行、密码、令牌或连接串。
4. MCP 未连接、查询超时或权限不足时，报告 `BLOCKED`/`PARTIAL`，不要改用猜测、历史数据或“看起来一致”代替当前证据。

## 查询流程

1. 先用对象检索确认 schema、表名和列名，不凭记忆猜字段。
2. 再按精确 ID 查询少量目标列；需要排序时明确排序键和上限。
3. 将结果与 API/页面返回的状态、数量、归属和时间核对。
4. 拒绝分支执行后再次查询，确认数据没有被修改。
5. 报告中只保留查询目的、表、ID、关键值、时间和结论，不粘贴整个结果集。

## 关键断言

以下字段按当前 schema 实际列名为准；先确认列存在，再查询：

| 业务对象 | 重点核对 |
|---|---|
| 漏洞 | 当前状态、修复状态、风险接受/加白状态、有效期限、归档时间和归档原因 |
| 工单 | 当前状态、归档原因、有效期限、原期限快照、办理人和审核人 |
| 加白/延期申请 | `application_type`、审核状态、是否有效、申请人和审核人、审核时间 |
| 资产认领 | 永久资产 ID 不变、组织/责任人已补齐、待认领与已认领不重复建档 |
| 导出/异步任务 | 任务终态、记录数、生成文件关联和失败原因 |
| 权限过滤 | API 返回对象必须在当前账号组织范围内；数据库只佐证范围结果，不替代认证和鉴权测试 |

## 典型闭环对账

- 人工办理：工单从待处置进入待审核，驳回后回到可继续办理状态，通过后归档；漏洞和动作历史与工单终态一致。
- 加白：审批通过后工单归档、申请生效，漏洞 `risk_accepted`/白名单状态更新，但修复状态不能因此变成已修复。
- 延期：审批通过后漏洞有效期限和工单有效期限更新，原期限快照保留，工单不能因延期被归档。
- 权限：只读账号写请求返回拒绝；跨组织账号查询不到无权对象；拒绝后数据库没有新增或修改。
- 影子资产：认领前后原主机 ID 不变，只迁移认领状态和责任关系，不产生第二台主机。

## 与 API 证据的关系

- API 返回业务成功，数据库仍保留旧状态：优先怀疑事务、映射或异步任务，结论为 `FAIL` 或 `PARTIAL`。
- 数据库已更新，API 查询仍返回旧值：检查缓存、数据权限、查询范围和响应映射，不能只凭数据库判页面通过。
- 页面和 API 都通过、数据库没有核对：可以判业务主路径通过，但不能声称持久化、事务或跨表一致性已验证。
