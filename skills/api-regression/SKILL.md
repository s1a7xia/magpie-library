# API 优先的业务回归

用真实接口验证用户能观察到的业务结果。默认优先使用项目运行时、HTTP 客户端和现有认证方式；关键状态、事务和跨表一致性用已连接的数据库只读 MCP（如 dbhub）补充证据。数据库 MCP 不可用时不阻塞 API 主路径，但数据库专属断言必须标为未验证。Skill 是方法，不是业务契约或执行授权。

## 使用顺序

1. 读取当前验收清单、未修缺陷、运行版本和受影响代码，只测约定范围内的未覆盖闭环。
2. 按 [环境与执行](references/environment.md) 确认目标环境、隔离方式、数据影响和可用运行器。
3. 按 [认证与账号生命周期](references/authentication.md) 建立每个角色的独立会话。复用已有登录态优先；只有一个引导管理员凭证时，由 agent 创建并维护衍生测试账号。
4. 按 [场景与断言](references/scenarios.md) 设计少量纵向流程，优先业务查询接口和真实持久化结果。
5. 对关键状态、事务、期限、归档、权限过滤和跨表一致性，按 [数据库只读核对](references/database-verification.md) 用数据库 MCP 查询精确 ID，和 API/页面结果对账。
6. 按 [结果与清理](references/reporting.md) 报告 `PASS / FAIL / PARTIAL / BLOCKED`，修复授权范围内缺陷并复测，清理本轮数据。

## 资源原则

- **必需：** 对目标环境可用的 HTTP/RPC 客户端、当前项目的认证协议与接口契约、获准使用的测试身份、唯一 run ID。
- **推荐：** 已连接的数据库只读 MCP（如 dbhub）用于关键持久化断言；项目已有 OpenAPI、任务系统日志和浏览器能力按范围使用。只为具体断言增加，不为“看起来更自动”安装工具。
- **不要求：** 专用测试框架、OpenAPI MCP、浏览器 MCP、多个子 agent。数据库 MCP 未连接时不是 API 主路径的前置条件，但数据库专属断言不能伪装为已验证。多角色用多个独立会话验证，不用多个 agent 代替。
- **必须停止：** 目标环境不明确、身份与角色不符、无授权写共享数据、外部依赖会产生真实客户副作用、运行版本与代码基线不一致。
- **缺少引导管理员密码：** 停止业务测试，直接告诉用户应填写哪个本地账号文件、哪一行和哪一列；不要泛泛提示“缺少凭证”。

## 核心约束

- API 通过不等于页面行为已验证；纯 API 任务不自行搭建浏览器测试。
- HTTP 200 不代表成功。同时检查传输状态、应用业务码、响应结构和最终事实。
- 数据库 MCP 只用于只读核对，不替代业务 API 或页面行为；API 成功但数据库终态不符时，结论不能是 `PASS`。
- 数据库查询必须使用本轮 API/页面返回的精确 ID 和有界条件，禁止无界 `SELECT *`、写入、DDL 或通过改库制造测试状态。
- 正向闭环配最关键的拒绝分支；不机械重复全部 CRUD。
- 权限必须用真实角色会话验证，不能用管理员会话冒充普通角色；页面保持未验证，除非当前任务明确要求并授权页面检查。
- 异步任务轮询明确终态和截止时间；超时报告阶段，不无限等待。
- 测试数据使用唯一 run ID；只清理有归属证明且获准删除的数据。
- 密码、Token、Cookie、连接口令不进入提交、报告或完整请求日志。

## 边界

真实厂商设备、外部情报、客户网络、生产调度和纯视觉体验无法由本地 API 测试证明时，标记 `BLOCKED` 或“范围外”，不用模拟结果写成通过。数据库 MCP 查询失败或当前连接不可用时，API 主路径仍可执行，但数据库证据明确记为未取得。
