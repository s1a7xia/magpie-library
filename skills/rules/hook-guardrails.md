# Hook Guardrails

Hook 是可选的平台适配层，用事件把工程边界变成确定性检查。它不是开发流程本身，也不替代 PRD、切片、页面验收、review 或用户授权。当前 Magpie 组合拳默认不安装 Hook；需要时由项目显式启用并登记，共享技能只描述契约。

## 事件与阶段

| 事件 | 在组合拳中的作用 | 允许的动作 | 禁止的动作 |
|---|---|---|---|
| `SessionStart` | 恢复项目上下文 | 注入 `docs/agents/project-state.md`、相关 PRD 的只读摘要 | 自动开始修改、自动运行 `implement` |
| `UserPromptSubmit` | 判断当前请求属于 Direct、Slice 还是 Baseline | 提示应加载的技能和阶段，保留用户选择的入口 | 自动串联 think → story → implement；替用户拍板业务分支 |
| `PreToolUse` | 拦截高风险操作 | 拒绝破坏性命令、越界写入、凭证写入；必要时返回明确的拒绝理由 | 静默改写用户意图；无审计地扩大权限 |
| `PermissionRequest` | 补充权限判断 | 对明确安全的项目命令自动放行，对不确定操作保持人工确认 | 用 Hook 绕过已有授权或审批策略 |
| `PostToolUse` | 记录实际发生的事实 | 记录命令、diff、错误和证据路径；把失败原样保留 | 把未运行的测试或验收写成通过；自动做全量测试或 lint |
| `Stop` | 检查交付声明 | 提醒补齐未验证项、未提交状态和阻塞 | 用模板文字替代真实证据；自动标记 `Accepted` 或 `Done` |
| `SessionEnd` | 交接与清理 | 写入无凭证的会话摘要、清理临时文件 | 自动提交、推送、部署或删除业务数据 |

Codex 与 Claude Code 的事件名和配置格式并不完全相同。读取或编写具体配置前，必须使用目标 Agent 的官方文档；不能把 Claude Code 的 `settings.json` 示例直接当成 Codex 配置。

## 设计约束

- **流程优先**：Hook 只能加固现有阶段边界，不能成为第二套工作流引擎，也不能创建隐式技能依赖。
- **最小权限**：只拦截当前任务明确涉及的路径和命令；不因 Hook 存在就扫描全仓、执行全量测试或访问网络。
- **高风险失败关闭**：破坏性命令、凭证外泄、越界写入必须拒绝；低风险观察型 Hook 失败时报告并继续，不得吞掉错误。
- **快速幂等**：Hook 要短时、可重复、无交互、无凭证输出；超时后按明确策略停止，不无限重试。
- **事实可追溯**：记录事件、命令、结果和证据路径；未执行的检查标记为未验证，不能写成通过。
- **平台适配**：共享技能只定义契约，具体脚本、matcher、trusted hash 和安装位置由目标 Agent 管理；项目级配置不得改动机器级索引。
- **默认关闭**：没有用户明确启用时，不安装 Hook，也不把 Hook 当作完成任务的前提。

## 推荐边界

优先只做三类 Hook：

1. **PreToolUse 安全护栏**：拦截 `rm -rf`、强制推送、数据库破坏性操作和明显凭证写入。
2. **Stop 交付护栏**：提醒缺少编译证据、页面验收、未提交文件或未解决阻塞；只提醒，不伪造状态。
3. **SessionStart / SessionEnd 交接护栏**：恢复项目状态，记录无凭证的交接摘要。

不建议为普通 CRUD、每次文件写入或每个技能自动运行测试、格式化、提交和页面验收。这些动作必须服从组合拳的显式阶段和当前用户授权。
