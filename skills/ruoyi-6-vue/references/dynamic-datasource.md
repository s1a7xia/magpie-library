# 动态数据源与多库访问参考

只在任务明确涉及多数据源、主从库、按业务切换数据库、`@DS`、`@DSTransactional` 或跨库事务时加载。普通单库 CRUD 不加载。

## 6.1.0 源码事实

- 动态数据源使用 dynamic-datasource，配置在 `spring.datasource.dynamic.*`，包含 `primary`、`strict` 和 `datasource`；当前开发配置默认 `master`，其他库以注释示例存在。
- `DataBaseHelper` 通过 `DynamicDataSourceContextHolder` 读取当前数据源键；生成器模块用 `@DS("#dataName")` 和 `@DSTransactional` 处理多库。
- `@DS("")` 可强制使用默认数据源；Mapper/Service 上的数据源切换和事务边界要按现有实现确认。

## 先判断方案

| 需求 | 选择 |
|---|---|
| 同一库内不同部门/客户数据隔离 | 数据权限，不是 `@DS` |
| 读写分离 | 先确认项目是否配置从库、复制延迟和一致性要求 |
| 按业务连接不同数据库 | 动态数据源，但要评估迁移、备份、权限和跨库查询 |
| 一次性导入另一个库 | 先确认授权和只读/写入边界，不把连接可用当授权 |
| 普通业务单库 | 不引入动态数据源配置 |

## 实现边界

1. **数据源键有边界**：`@DS` 的键必须来自受控配置，不接受用户任意字符串；`strict: true` 时未命中会报错。
2. **切换范围最小**：在 Service/Mapper 明确范围内切换，调用结束恢复上下文；异步线程和回调不会自动继承线程上下文。
3. **事务边界**：普通 `@Transactional` 只管当前数据源；跨库写入需要 `@DSTransactional` 或明确的补偿方案，并验证失败回滚。
4. **连接与池**：每个数据源有独立连接池、超时和健康检查；新增库要评估连接数、故障隔离和监控。
5. **权限与审计**：跨库访问仍受用户权限和数据范围约束；日志不输出 DSN、账号或密码。
6. **迁移与备份**：新增库/表要有脚本、版本和回滚计划；不能因为本地连接成功就在生产执行。
7. **一致性**：跨库无全局事务时，明确最终一致性、重试和人工补偿；不要在业务代码里假设原子提交。

## 验证

- 验证目标数据源命中、默认库回退、错误键、连接失败和事务回滚。
- 多线程/异步场景验证上下文不会串库；跨库写入验证失败补偿。
- 数据库操作前只读核对目标、库名和影响范围；写入和批量变更需要明确授权。
