# RuoYi 6.1 Vue Page Design

本文件是 plus-ui 6.1.0 Vue 页面的视觉与验收边界。`frontend-design` 负责设计方法；本文件负责让业务页保持既有产品的一致性。视觉改动不改变权限、字典、分页、校验、请求和既有交互。

实际 token、组件和样式类以目标 plus-ui 版本为准。6.1.0 Vue 已有一套页面壳和主题系统，动手前先读：

- `src/assets/styles/tokens/_theme.scss`、`_theme-dark.scss`
- `src/assets/styles/components/_page-shell.scss`
- `_search-panel.scss`、`_table-toolbar.scss`
- 两三个同模块兄弟页面

## 1. 先选界面模式

| 模式 | 页面 | 取向 |
|---|---|---|
| **Operate** | 业务 CRUD、列表、表单、弹窗、配置、审批、详情 | 精准与克制。Element Plus 和若依内置组件就是设计系统，做层级、密度、状态和信息表达 |
| **Experience** | 登录页、工作台首页、态势大屏、独立展示页 | 视觉表现力放开。可用深色主题、高对比度 KPI 和 ECharts 联动，但仍使用真实数据与既有权限 |

不要把独立站的“工作室视觉”套进业务页，也不要让业务页的表格和弹窗限制独立展示页。模式判断错误，比缺少装饰更伤页面。

## 2. 页面配方

### 列表页

- **页面壳**：复用 `p-2`、`app-container` 和现有间距；`p-2` 已是纵向 flex + 12px gap，不要再叠加一层大卡片。
- **筛选区**：筛选较多时用现有 `search-panel` / `search-wrap` 结构，支持 `is-collapsed` 折叠；搜索是主按钮，重置是次按钮。不要重复放同一组筛选。
- **操作区**：复用 `toolbar-shell`、`table-heading`、`toolbar-actions`、`panel-kicker`；主操作只有一个，新增、修改、删除、导出按权限和频率排列，保留 `right-toolbar`。
- **表格**：状态用 `dict-tag` 或语义化 `el-tag`；时间、数字、长文本的列宽和对齐稳定；长文本用省略号加 tooltip，不强行撑宽页面；行操作用固定宽度和 link 按钮，沿用 `data-table` 的 28–32px 链接按钮规格。
- **分页**：保留现有 `pagination`；窄屏隐藏不必要的跳页/页大小控件，不制造横向滚动。
- **指标卡**：只有数据真实支撑时才加 2–4 个 KPI；每个数字回答一个实际问题，不做装饰性统计，不与操作区抢焦点。

### 新建 / 编辑

- 字段少、单一表单优先 `el-dialog`；字段多、分区多或要并列关联信息时用 `el-drawer` 或独立页。不要为了“高级感”把简单表单做成大屏。
- 统一 label 宽度、字段顺序和必填标记；宽屏两列、窄屏一列时保持相同阅读顺序。底部沿用若依兄弟页面的操作顺序（通常“确定”在左、“取消”在右）。
- 保留校验、提交 loading、失败恢复和取消/关闭行为。弹窗内部不再套多层卡片；用分区标题和留白组织信息。

### 详情

- 标题区先回答“这是什么、当前什么状态、能做什么”，状态标签靠近标题或首屏摘要。
- 用分组标题和 label/value 节奏组织信息；宽屏两列、窄屏一列，长文本可折叠。操作按钮与编辑页保持同一套权限和文案。
- `el-drawer` 适合从列表快速查看；需要深链、复杂编辑或大量关联时用独立详情页，不把抽屉塞成第二个后台。

### 树表 / 左右分栏

- 复用现有 `TreePanel`、`el-tree-select`、`useTreeCollapsed` 和左右分栏比例；树可折叠时保证内容列获得宽度。
- 树的搜索、选中、空节点、加载状态和键盘操作都要保留；右表筛选不能因树状态丢失。
- 窄屏改为上下或可折叠结构，禁止整页横向溢出。

### 工作台 / 大屏

- 先定一个核心问题和一条视觉主线，再排 KPI、趋势、分布和明细。KPI 不是四张同尺寸卡片的默认套餐；只保留真正驱动决策的指标。
- 图表使用真实接口和统一时间范围；ECharts 主题、tooltip、空数据和加载态一起设计。深色模式用现有 token，不散落硬编码颜色。
- 信息层级遵循“总览—异常—下钻”，允许不对称布局；动画只服务于变化和注意力，不装饰每一块。

### 登录 / 独立展示

- 可以使用完整视觉方向、品牌图形和深色主题；但登录失败、验证码、加载和键盘焦点必须有清晰状态。
- 不复制公开后台模板的皮肤。参考其信息层级、密度和状态设计即可。

## 3. 视觉系统

- 先读现有主题 token 与页面壳。6.1.0 Vue 已有 `--app-*`、`--el-*`、`app-container`、`search-panel`、`table-panel`、`toolbar-shell`、`toolbar-actions`、`panel-kicker`、`data-table` 等；优先复用，不存在就不要为了“统一”擅自新建全局同名类。
- 颜色通过主题层和语义变量调整。Operate 页的状态色固定表达含义：成功/正常用 success，待处理/警告用 warning，失败/危险用 danger，未知/停用用 info；不要把所有状态都染成 primary。
- 字号保持产品级克制：正文 14px 左右，区块标题 15–16px；不靠超大标题制造层级。间距优先 8/12/16/24 的现有刻度，少用边框，用留白分组。
- 一个页面只设一个视觉焦点。主操作、标题和当前状态比装饰更重要；所有元素同等重量是“丑”的常见根因。
- 复用现有组件、hooks 和样式。单页需求不覆盖全局样式，不为单页引入新字体、动画库或第二套表格/弹窗。

## 4. 反廉价感禁令

Operate 页面严禁以下默认写法：

- **侧边粗色条**：卡片或列表项左侧一条粗彩色边框。状态用标签或状态块表达，不靠色条提神。
- **渐变字**：正文或标题使用渐变填充。它损害对比度和可读性，也是最典型的生成页痕迹。
- **无意义毛玻璃**：没有层级或景深理由的半透明/模糊堆叠。它会糊掉文字并拖慢渲染。
- **装饰性指标卡**：没有真实数据、没有决策用途的数字卡片。
- **卡片套卡片**：每一块都加圆角、阴影和边框，导致页面没有层级。

Experience 模式下渐变、玻璃面板、彩色描边可以作为刻意选择，但必须说明它服务的目的；不能因为“看起来高级”就默认加上。

## 5. 状态设计

每个列表、表单和详情都要检查：

- **加载**：表格/图表有明确加载态，避免空白和布局跳动。
- **空**：说明为什么为空，并给下一步动作（新增、调整筛选、清空筛选）。
- **错误**：显示可理解的错误和重试入口，不把原始异常或敏感信息直接暴露给用户。
- **无权限**：说明缺少权限或引导联系管理员，不伪造按钮，不静默失败。
- **未保存/提交中**：关闭、重复提交和失败回填行为明确。

## 6. 交付底线自检

以下必须在渲染页面核过，不以源码判断：

- **无意外横向滚动条**：窄视口下没有元素把页面撑出横向滚动；宽表格和长字符串被容器约束，而不是溢出或截断。
- **按钮文字不折行**：任何宽度和文案下按钮文字保持单行；折行说明容器太紧，不是文案太长。
- **深色模式对比度可读**：正文、次要文字、边框、禁用态和图表标签在深色背景上清晰可读，不只亮色模式。
- **z-index 无遮挡冲突**：`el-dialog`、`el-select` 下拉、日期选择、`el-tooltip`、`el-drawer` 层级正确，不被遮住或裁切。
- **键盘与焦点可见**：表单控件、按钮、树和弹窗可用键盘到达，焦点样式可见。

## 7. 视觉验收

视觉结论以渲染结果为准。改版后按 [page-acceptance](../../page-acceptance/SKILL.md) 走一遍主路径和一个边界（窄视口、长文本、空表格或无权限），保留截图作为证据。仅编译通过或只读源码，不构成美化成败的依据。
