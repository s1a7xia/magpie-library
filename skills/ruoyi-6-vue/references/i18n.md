# 国际化与文案参考

只在任务涉及多语言、`content-language`、消息资源、后端提示文案、前端语言包或翻译字段时加载。单语言项目不加载。

## 6.0.0 源码事实

- 后端消息资源在 `ruoyi-admin/src/main/resources/i18n/messages.properties`、`messages_zh_CN.properties`、`messages_en_US.properties`；`spring.messages.basename=i18n/messages`。
- `I18nLocaleResolver` 从请求头 `content-language` 解析 Locale，缺省回退系统默认；当前不支持服务端主动切换。
- `MessageUtils.message(code, args...)` 读取 `MessageSource`，缺失 code 时返回 code 本身；业务异常和 `@RepeatSubmit`/`@RateLimiter` 的 `{code}` 消息可复用该机制。
- 通用翻译是另一层能力：`@Translation` + `TranslationInterface` 把用户、部门、字典、OSS 等 ID 转成展示值；翻译是数据展示，不是多语言资源。

## 实现边界

1. **先确认项目是否真的多语言**：检查前端语言包、后端 i18n 文件、请求头和现有页面；没有完整链路时不要只给新页面加半套翻译。
2. **资源键稳定**：使用业务域前缀和明确语义，所有语言文件同步新增；不要用中文句子当 code。
3. **参数化**：动态内容用占位参数，不拼接整句；数字、日期、货币按 Locale 格式化。
4. **前后端分工**：后端返回业务错误 code/消息，前端负责按钮和静态文案；同一文案不要在多处重复维护。
5. **缺失回退**：缺失翻译时明确回退语言或显示 code，不能静默空白；测试至少覆盖中文和英文。
6. **数据翻译与语言翻译分开**：字典标签、用户/部门名称用 `@Translation`/字典；界面语言用 i18n 资源，不要混为一套。
7. **编码与长度**：properties 文件编码、UTF-8 和不同语言长度影响布局；按钮和表格列要在目标语言下验收。

## 验证

- 切换语言或请求头后验证页面、校验提示、接口错误和导出文件；刷新后语言状态保持符合设计。
- 检查缺失 key、参数占位、长英文/中文换行和窄屏布局；按钮文字不折行。
- 涉及可见页面时按 `page-acceptance` 做至少两种语言的渲染验收。

官方参考：[Spring Internationalization](https://docs.spring.io/spring-boot/reference/features/internationalization.html)。资源路径和前端语言方案以目标工程为准。
