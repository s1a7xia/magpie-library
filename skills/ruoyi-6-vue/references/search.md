# Elasticsearch / Easy-ES 搜索参考

只在任务涉及全文检索、搜索索引、Easy-ES Mapper、Elasticsearch 同步或复杂搜索页时加载。普通 CRUD 不加载。

## 工程内实现入口

- 搜索能力在 `ruoyi-common/ruoyi-common-elasticsearch`，基于 Easy-ES `3.0.2` 和 Elasticsearch Client `7.17.28`。
- `EasyEsConfiguration` 由 `easy-es.enable=true` 条件启用，并扫描 `org.dromara.**.esmapper`；包名调整时必须同步修改扫描入口。
- 开发配置键是 `easy-es.*`，包含地址、协议、认证、超时、连接池、DSL 日志、索引阻塞、驼峰映射、ID 策略、字段更新策略和刷新策略；默认关闭。
- 当前公共模块只提供自动配置和健康检查联动，没有通用搜索业务表或索引模型。业务索引、同步和查询属于具体模块。

## 先判断是否需要搜索

| 需求 | 选择 |
|---|---|
| 简单条件筛选、分页、排序 | 先用数据库和现有 `QueryBuilder`；不要为少量数据引入 ES |
| 多字段模糊、相关性排序、聚合、海量检索 | 评估 Easy-ES，并确认部署、数据量、同步延迟和运维成本 |
| 只需要前端过滤当前页 | 不建索引 |
| 搜索结果是权限敏感数据 | 搜索层仍要带用户、部门等过滤，不能只靠前端隐藏 |

## 实现边界

1. **先读现有索引和同步链路**：查 `esmapper`、索引实体、初始化脚本、同步任务/事件和前端搜索 API；沿用项目的索引命名和版本策略。
2. **数据库是事实源**：明确新增、修改、删除、批量导入和补偿如何同步索引；同步失败可重试、可观察，不能只写 ES。
3. **索引与 DDL 分开管理**：索引 mapping、分词器、别名和重建流程要可重复执行；修改字段类型前评估重建和数据迁移。
4. **权限和数据范围**：查询条件包含数据范围；高敏感字段是否进入索引要单独判断，索引和日志都不能存明文密钥。
5. **分页与深分页**：遵守 ES 的窗口限制；需要大量导出或深分页时使用项目约定方案，不在单次查询拉全量。
6. **刷新策略**：`refresh-policy` 影响可见延迟和写入成本；测试要等待索引可见，不要把“刚写入未搜到”误判为业务失败。
7. **降级**：ES 不可用时明确是报错、回退数据库还是隐藏搜索入口；不要静默返回空结果冒充“没有数据”。

## 验证

- 验证索引创建、文档新增/更新/删除、重建和查询结果；用中文、英文、空值、特殊字符和长文本检查分词与排序。
- 验证无权限用户、不同部门不会通过搜索越权。
- 涉及搜索页面时按 `page-acceptance` 验证加载、空状态、错误状态、分页和筛选重置。
