## 实现边界

- 遵循已确认的业务对象、归属、状态、权限、唯一性、删除和验收规则；实现中发现契约冲突或缺少关键决定时，停止受影响部分并说明影响，不自行改业务口径。
- 功能权限与数据权限分开。后端权限是安全边界，菜单/按钮隐藏只是界面行为。
- 只处理当前改动涉及的事务、幂等、状态、并发、缓存、异步和异常路径，不预埋通用框架。
- 字典只承载有限枚举；参数只承载运行期配置；业务身份、归属、唯一键、状态和常用查询字段落真实列。
- 当前切片涉及持久化数据时读取 `database.md`。若业务身份、归属、关系、唯一性、生命周期、删除语义或 JSONB 模型尚未决定，先由 `database-design` 形成契约；已确认契约的字段链路和增量脚本落点由本技能承接。设计、写脚本和执行数据库变更不是同一授权。
- 业务规则未定时按当前业务最安全、最可逆的默认方式完成可运行实现，并留下 `TODO(待确认)`：待确认什么、当前实现、后续调整条件、确认人。TODO 不得掩盖缺失能力、空白按钮或跳过校验；不可逆或扩大权限的动作不擅自决定。
- 只有当前请求明确授权时，才运行构建、测试、页面检查、数据库操作、提交或推送；未执行时如实标记未验证。

## 前后端与路由契约

创建或修改业务页面时，至少核对本次涉及项：

- 后端 Controller/Service/Mapper、请求 BO、响应 VO 与前端 `types.ts` 的字段、可空性和 ID 精度一致。
- API 路径、HTTP 方法、分页结构和前端请求函数一致。
- 菜单 `component`、`dynamicPage.tsx` 注册键、页面路径和权限字符一致；不发布没有实现入口的空菜单。
- 权限字符在菜单/按钮、后端注解和前端 `hasPermi` 三处一致。
- 列表、详情、写入、批量、导出和关联对象使用与业务契约一致的数据范围。
