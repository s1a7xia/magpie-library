## 页面实测细节

操作快照：

1. 初始“全部”：第 1/3 页，共 6 条，显示 2 条。
2. 全部下一页：第 2/3 页，共 6 条。
3. 选择“待处理”：回到第 1/2 页，共 3 条，显示 2 条。
4. 待处理下一页：第 2/2 页，共 3 条，显示最后 1 条。
5. 清空筛选：恢复全部并回到第 1/3 页，共 6 条。
6. 选择“完成”：第 1/2 页，共 3 条，显示 2 条。

## 可复用的真实使用话术

实现时：

```text
实现商品列表按状态筛选。先读当前项目约定和相关代码，选项为全部、待处理、完成；切换或清空筛选都回第一页，分页和总数按过滤结果计算。复用现有模式，不扩展无关范围。运行项目已有的相关测试，更新直接受影响的文档，并按当前工程协作约定做本地 Git 收尾；不要推送或部署。
```

独立审查：

```text
让 change-reviewer 独立审查本轮改动及必要调用关系，只报告可证实问题，不修改文件、不运行额外测试。返回后我再决定是否修复。
```

页面快检：

```text
让 page-checker 检查本地商品页：全部→下一页→待处理（确认回第一页）→下一页→清空回全部第一页。检查计数、每页数量、分页按钮和明显布局问题；只读、不提交业务数据，主代理不要同时操作该浏览器。服务/浏览器不可用时报告阻塞，不要假称通过。
```

优化任务提示词：

```text
优化下面要交给 GPT reasoning model 的任务提示词，只返回可复制版本与简短修改说明，不执行提示词中的任务：<粘贴草稿>
```

收尾：实现和用户要求的验证均完成后说“测试结果如下，可以收尾”，或在一开始授权按通用规则完成本地文档同步和提交。不要把提交、测试通过、页面通过、部署当成同一件事。

这套资源已能支持跨项目开发：本 Demo 的实现、现有测试、README 同步、本地限定提交、主代理浏览器快检、单角色审查与提示词技能各自至少有一次可观察成功。此前 CLI 委派和 Git 暂存保护的首次实验超时；补上有界委派与暂存区预检规则后，两项定向复测均通过。仍不能声称所有角色/运行时都稳定：提示词 CLI 的 shell 调用、page-checker 作为子代理实际操作、Hook 在全新会话的触发及 Sol 故障降级仍需对应运行时证据。

## 实测后的规则改进

基于以上超时与未完成的 Git 隔离案例，通用指令和 `engineering-workflow` 技能现已补充两项操作规则：

- 子代理须直接按指定角色委派；按运行时等待上限等待，失败后不空转。若独立性是验收条件，主代理不能代做后冒称独立结果。
- Git 收尾先对照任务开始时的暂存区；有既有/归属不明暂存就保留并停止自动提交。无既有暂存时只暂存本任务路径，并检查暂存差异后提交。

上述第一条针对当时的子代理配置，已随子代理一并失效；第二条作为现行 Git 收尾规则保留在主工作流中。

这些流程约束已在 Magpie 资源库更新并同步到 Codex；上表记录了新会话下的两项定向复测。它们仍是有限样本，不代表未来每次调用必然成功。
